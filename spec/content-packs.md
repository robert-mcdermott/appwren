# Content packs

AppWren ships its starting content as **packs**: data files that are loaded into the database, versioned, and replaceable. The whole program configuration is a pack; so, from later waves, are starter capability maps and technology catalogs. A revised question bank, a re-weighted profile, or another organization's way of working arrives as a pack, never as a code change ([ADR-0007](decisions/0007-program-as-data.md)).

## Kinds of pack

| Kind | Holds | Loaded into | Wave |
|---|---|---|---|
| **Program** | Vocabularies, the organization's own fields, the questionnaire, the scoring model (profiles, rules, guardrails, flags, cadences), visibility, and the definition of an application | Program settings, `questionnaire`, `scoring_model` | 1 |
| **Capability map** | A tree of capabilities with descriptions | `capability` | 1 |
| **Technology catalog** | Technologies with kinds and the keys that match an end-of-life dataset | `technology` | 2 |
| **Starter program** | A program, a capability map, and bands sized for a kind of organization | All of the above | 7 |

## Format

A pack is one JSON document. JSON is chosen because the standard library reads and writes it, it diffs well enough in review, and it needs no parser dependency.

```json
{
  "pack": {
    "key": "default-program",
    "kind": "program",
    "title": "AppWren default program",
    "pack_version": "1.0.0",
    "license": "Apache-2.0"
  },
  "vocabularies": { "sourcing": [ { "key": "saas", "label": "Software as a service", "help": "…" } ] },
  "fields": [ { "key": "irb_protocol", "label": "Ethics protocol", "type": "text", "section": "research" } ],
  "questionnaire": { "sections": [ { "key": "value", "questions": [ { "key": "strategic_fit", "levels": ["…", "…", "…", "…", "…"] } ] } ] },
  "scoring": { "profiles": [ … ], "rules": [ … ], "guardrails": [ … ], "flags": [ … ], "cadences": { … } },
  "capabilities": [ { "key": "research", "name": "Research", "children": [ … ] } ]
}
```

- A pack is checked whole before anything is written. A pack with anything wrong is refused whole, with every problem listed: a key used twice, a factor naming a fact that does not exist, weights that do not add up, bands that do not rise, a rule whose condition refers to an unknown fact, a field of an unknown type.
- Loading is a dry run first: it reports what would be added, changed, and left alone.
- **The program is installed, not migrated.** Migrations build tables; `appwren init` and `appwren db upgrade` then add whatever of the default program is missing, as ordinary audited writes, and never overwrite what an organization has shaped.
- Built-in packs live in `src/appwren/resources/packs/`. The default program is generated by `scripts/build-default-program.py` from readable sources in the script, so that a change to it is reviewed as a change to the script.
- `appwren program export` writes the installation's own program as a pack; `appwren program import` loads one, with `--dry-run`.

## What text may be shipped

Everything in a built-in pack is written for AppWren and licensed with it under Apache 2.0. Packs do not reproduce text from other publishers. Where a vocabulary follows a public standard, the pack names the standard and its publisher and uses only the codes and short names.
